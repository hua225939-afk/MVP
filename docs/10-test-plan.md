# Vibe Coding 第一阶段测试计划

## 1. 测试目标

测试需要证明：

- 五种演示身份可以进入对应页面，并只看到正确范围的统一模拟数据。
- 课程 JSON 结构正确，13 课都通过同一渲染链路。
- 学习进度能在本地可靠保存和恢复。
- 学生学习与教师预览不会互相污染。
- 电脑和平板可使用。
- lint、类型检查和 build 始终通过。

当前仓库尚未配置单元/E2E 测试框架。本计划描述目标测试集；实施时优先选择与现有 Next.js/React 技术栈兼容的最小工具组合，不在本轮安装依赖。

## 2. 测试层级

| 层级 | 目标 | 建议内容 |
| --- | --- | --- |
| 静态检查 | 代码质量和类型安全 | ESLint、TypeScript、build |
| Schema 单元测试 | 内容和模拟数据约束 | Zod parse 成功/失败 |
| 组件测试 | 互动原子的行为 | 输入、反馈、完成结果 |
| Repository 测试 | 五角色数据范围 | 同源数据、过滤和汇总 |
| 集成测试 | 课程渲染与进度存储 | JSON → Renderer → store |
| E2E | 真实路由与用户流程 | 五端导航、学习、刷新 |
| 视觉/设备测试 | 布局与触控 | 电脑与平板尺寸 |

## 3. 五角色页面测试

### 3.1 公共入口

- `/` 显示产品说明、五个身份入口和演示数据说明。
- 五个入口分别进入 `/hq`、`/partner`、`/teacher`、`/student`、`/parent`。
- 不出现真实登录、注册、支付或 AI 密钥入口。

### 3.2 总部端

| 页面 | 核心断言 |
| --- | --- |
| `/hq` | 校区、班级、教师、学生、完成率、作品数来自明细汇总 |
| `/hq/courses` | 显示 5 单元、13 课，顺序与课程清单一致 |
| `/hq/components` | 原子组件列表与课程 JSON 实际引用一致 |
| `/hq/campuses` | 可见全部校区，数量与 mock 数据一致 |
| `/hq/analytics` | 各维度汇总使用统一公式，无手写冲突数字 |

### 3.3 合作伙伴端

| 页面 | 核心断言 |
| --- | --- |
| `/partner` | 明确显示当前模拟合作伙伴及所属校区 |
| `/partner/campuses` | 只显示所属校区 |
| `/partner/classes` | 只显示所属校区班级 |
| `/partner/teachers` | 只显示相关教师 |
| `/partner/schedule` | 排课中的班级、教师、课次引用有效 |

负向测试：不能通过 UI 或 query 参数看到其他合作伙伴校区的数据。

### 3.4 教师端

| 页面 | 核心断言 |
| --- | --- |
| `/teacher` | 只汇总本人 TeachingAssignment 范围 |
| `/teacher/classes` | 只显示本人班级和正确学生数 |
| `/teacher/courses` | 可查看 13 课清单并进入只读预览 |
| `/teacher/students` | 进度、测试和作品属于本人班级学生 |
| `/teacher/works` | 作品与学生关联正确；模拟评价按已确认规则操作 |

关键负向测试：教师预览课次后，学生 localStorage 进度、互动答案和作品都不变化。

### 3.5 学生端

| 页面 | 核心断言 |
| --- | --- |
| `/student` | 显示本人课程进度、作品和模拟奖励 |
| `/student/courses` | 5 单元、13 课状态正确，继续学习定位正确 |
| `/student/works` | 只显示本人作品，关联课次有效 |
| `/learn/[courseId]/[lessonId]` | 六步可导航，互动完成控制下一步，进度保存 |

需要覆盖：

- 新学生无进度。
- 已开始课次继续学习。
- 已完成课次显示 100%。
- 错误答案不能把必做互动标记为完成。
- 最后一步完成后课次状态正确。
- 不存在的 course/lesson 返回 404 或明确错误页。

### 3.6 家长端

| 页面 | 核心断言 |
| --- | --- |
| `/parent` | 只显示关联孩子的摘要 |
| `/parent/progress` | 5 单元、13 课状态与数据源一致 |
| `/parent/works` | 只显示允许家长查看的成果，不展示复杂代码 |
| `/parent/feedback` | 只显示 `student_and_parent` 可见反馈 |

负向测试：不显示其他学生、教师内部备注或详细调试记录。

## 4. 课程 JSON 验证

### 4.1 合法内容

- Course 的 `schemaVersion`、ID、版本和状态合法。
- 恰好 5 个 Unit，合计引用 13 个不重复 Lesson ID。
- 每个 Lesson 的 ID、order、courseId、unitId 匹配。
- 每课恰好 6 步，顺序严格为“看、讲、想、做、测、说”。
- 步骤 ID 和互动原子 ID 在规定范围内唯一。
- `teacherNotes`、`studentContent`、`parentSummary` 必填字段齐全。
- 每步至少一个互动原子。
- 必做原子与完成规则一致。

### 4.2 非法内容用例

每项都应断言 Zod 解析失败，并包含可定位路径：

- 缺少第六步。
- 六步顺序错误或重复。
- `lesson-14` 或 order 超出 1–13。
- Lesson 引用不存在的 Unit。
- Unit 重复引用同一 Lesson。
- Choice 的 `correctOptionId` 不存在。
- completion 引用不存在的 atom ID。
- 重复 atom ID。
- `runTest` 没有测试项或 `testMode` 非法。
- 颜色、日期、版本或 ID 格式错误。
- 严格对象出现未识别字段，暴露拼写错误。
- 第 12 课缺少 `keyConcepts` 时应失败，直到产品确认内容。

### 4.3 全课程一致性

- Loader 能发现索引中的全部课次。
- JSON 文件存在但未注册时检查失败。
- 索引引用课次但文件缺失时检查失败。
- 原子组件 registry 覆盖所有 `atom.type`。
- 课程地图、教师课程表和总部课程结构读取同一 Course。

## 5. 互动组件测试

| 组件 | 必测行为 |
| --- | --- |
| Reveal | 初始隐藏；点击后显示；发出 completed 结果；恢复已完成状态 |
| Choice | 未选择不可提交；正确/错误反馈来自 JSON；错误不完成；再次选择可重试 |
| TextInput | oneOf、minLength、normalize；空值禁用；自由表达不被唯一答案限制 |
| CodePreview | 代码和预览内容来自 JSON；确认后完成；按钮演示不污染学习结果 |
| RunTest | 初始未运行；部分/全部通过；修改后重跑；明确 contains 模式不执行代码 |
| LessonRenderer | 每个判别类型分发正确；未知类型在 Schema 阶段被拒绝 |

无障碍基础断言：

- 交互可通过键盘完成。
- 输入有 label，状态反馈使用可感知的语义。
- 焦点样式可见。
- 按钮 disabled 状态明确。

## 6. 学习进度保存测试

### 6.1 单元测试

- SSR 环境无 `window` 时返回空状态。
- localStorage 无键时返回空状态。
- 合法记录读取后不丢字段。
- 损坏 JSON、未知版本和字段类型错误安全回退。
- `currentStepId` 指向不存在步骤时按迁移策略处理。
- 完成互动后保存 value、completed、correct、attempts、updatedAt。
- 完成步骤后不重复添加 step ID。
- 完成课次后 status、completedAt、百分比一致。
- 旧 `vibe-course-progress:{lessonId}` 能迁移或安全兼容。

### 6.2 集成/E2E

1. 进入第 01 课。
2. 完成“看”和“讲”。
3. 刷新页面。
4. 断言仍停留在正确步骤，已有答案与完成状态恢复。
5. 返回课程地图。
6. 断言课次进度百分比更新。
7. 切换到教师预览并操作。
8. 返回学生端，断言进度未因教师预览变化。

另测：

- 第 01 课和第 06 课数据完全隔离。
- 两个 demo student 使用不同 key 时数据隔离。
- 达到存储异常时页面给出可恢复行为；具体用户提示在实现阶段确定。

## 7. 模拟数据一致性测试

- 所有外键存在。
- 总部学生总数等于 Campus/Class/Enrollment 明细计算结果。
- 合作伙伴统计等于其所属校区明细。
- 教师班级学生列表与 Enrollment 一致。
- 家长孩子与 ParentStudent 一致。
- 作品作者、课程和课次存在。
- 教师反馈关联对象存在，visibility 合法。
- 同一课次在五端展示的标题和单元来自课程 JSON，不出现复制文本漂移。

如确认跨角色本地联动，再增加：

- 学生保存作品后，同一浏览器教师端出现该作品。
- 教师添加模拟评价后，家长端出现允许家长查看的评价。
- 清除本地 override 后恢复基线 mock 数据。

## 8. 电脑和平板适配

### 8.1 目标视口

至少测试：

| 设备类型 | 视口 |
| --- | --- |
| 桌面 | 1440×900 |
| 小型笔记本 | 1280×800 |
| 横屏平板 | 1024×768 |
| 竖屏平板 | 768×1024 |

手机不是第一阶段核心验收设备，但现有 520/760 px 降级不能被明显破坏。

### 8.2 通用检查

- 无页面级横向滚动。
- 导航、卡片、表格和课程六步导航不遮挡。
- 主要按钮触控尺寸至少约 44×44 px。
- 固定头部不遮盖内容。
- 表格在平板有明确降级方案：横向容器或卡片化，不压缩到不可读。
- 输入时软键盘不遮挡当前操作。
- 文字对比度、焦点、错误和成功状态不能只依赖颜色。
- `prefers-reduced-motion` 下不依赖动画表达完成状态。

### 8.3 课程页专项

- 1024×768 时教师提示和主互动区均可用。
- 768×1024 时侧栏按设计堆叠，步骤导航可触控滚动。
- CodePreview 和 RunTest 双栏在空间不足时变单栏。
- 长代码、长中文文案和 6 个步骤不会撑破容器。

## 9. 质量命令

当前项目已有：

```bash
npm run lint
npm run build
npm test
```

`npm test` 当前只串联 lint 和 build。`package.json` 暂无独立 `typecheck` 脚本，因此在添加脚本前使用：

```bash
npx tsc --noEmit
```

后续建议加入：

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "test:unit": "<selected-runner>",
    "test:e2e": "<selected-runner>",
    "validate:content": "<course-schema-validation-command>",
    "check": "npm run lint && npm run typecheck && npm run test:unit && npm run validate:content && npm run build"
  }
}
```

具体测试框架在实施阶段选择，本轮不添加依赖。

## 10. 每阶段退出标准

每个实施阶段必须满足：

- 新增行为有对应测试或明确的人工验收步骤。
- 相关课程 JSON 和 mock 数据通过 Zod。
- 无未解释的 lint 错误或 TypeScript 错误。
- 生产 build 成功。
- 目标电脑和平板视口通过本阶段页面检查。
- 不删除现有可用功能；若有兼容影响，已在变更前说明并记录。
- 未确认功能保持 TODO，不以假实现冒充已完成。

## 11. 五端动态联动契约测试

- 学生课程进度通过 `LearningProgressRepository` 写入并恢复。
- 教师视图从同一 `ProjectRepository` 读取学生项目。
- 教师评语写回平台记录，并在学生与关联家长视图出现。
- 家长查询只返回演示关系中关联的学生。
- 合作伙伴统计由校区范围内的班级、师生、进度、项目和发布明细计算。
- 总部统计由同一明细与课程/工具注册表计算。
- 角色切换只改变页面，不清除进度、项目或评语。
- 旧进度键和旧项目结构迁移后仍保留数据。
- 初始化与角色切换不会重复创建课程主项目。
- 总部课程和组件页读取 13 课内容及实际注册表，不维护第二份清单。

## 12. 教师工作流与公共页面回归

- 五角色导航分别渲染角色业务入口以及消息、我的、设置入口，公共入口携带正确角色上下文。
- `/profile` 和 `/messages` 按角色展示不同摘要；`/settings` 与 `/help` 保持静态演示边界。
- `/teacher/students` 的学生卡片和列表行使用真实链接进入 `/teacher/students/[studentId]`。
- `/teacher/evidence` 的证据卡使用 button 打开可关闭、可键盘操作的详情层，并提供点评入口。
- `/teacher/reviews` 保存简短评语、优点、建议和关注标记后，学生端与关联家长端可从同一 `PlatformRepository` 读取。
- 演示班级、用户、消息和公共页资料集中管理；所有引用 ID 与统计汇总保持一致。
- 1440、1280、1024 宽度下不得出现页面级横向滚动；1024 宽度侧栏降级为可横向浏览的导航，证据详情层使用全宽布局。
