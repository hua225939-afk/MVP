# Vibe Coding 第一阶段实施计划

## 1. 实施原则

- 每个阶段都可以独立演示、测试和验收。
- 不删除现有可用学生 MVP；迁移路由或数据结构前先提供兼容方案。
- 五端框架先于样板课完整开发。
- 第 01 课和第 06 课作为两种难度的样板。
- 两节样板获得确认后，才批量接入其余 11 课。
- 每阶段结束运行 lint、类型检查和 build，并执行该阶段新增测试。

## 2. 阶段 0：基线与决策确认

### 修改范围

- 维护 `docs/06-architecture.md` 至 `docs/10-test-plan.md`。
- 确认模拟 AI、教师预览、跨角色联动、样板范围。
- 建立后续变更清单，不修改业务页面。

### 完成标准

- 当前 MVP 的保留、重构、暂缓清单获得确认。
- 所有阻塞问题有明确结论或标记为不进入当前阶段。
- 路由、Schema、数据模型和测试口径一致。

### 测试方式

- 人工文档审查：术语、路由数、角色范围、13 课顺序一致。
- 检查 Markdown 内 JSON 示例可解析。

## 3. 阶段 1：共享数据与课程基础设施

### 修改范围

- 新建 Course/Unit/Lesson/Step/Interaction Zod Schema。
- 新建课程清单、课次索引与全量校验命令。
- 新建统一 mock database、Repository 接口和 demo session。
- 新建版本化 progress store 接口与 localStorage 实现。
- 保留旧三课加载和旧进度读取的兼容层。

### 完成标准

- 课程清单可以表达 5 单元、13 个课次 ID，但此阶段不要求写完 13 课正文。
- 第 01/06 课可被 loader 独立发现；缺少的其余正文有明确 draft/index 状态，不伪造内容。
- mock 数据所有外键有效，五端查询来自同一数据源。
- 旧 `vibe-course-progress:*` 数据不会导致页面报错。

### 测试方式

- Zod 单元测试：合法/非法课程、重复 ID、六步错序、错误引用。
- Repository 契约测试：五角色数据范围。
- progress store 单元测试：空数据、损坏 JSON、迁移、保存与恢复。
- `npm run lint`、类型检查、`npm run build`。

## 4. 阶段 2：公共入口与五端框架

### 修改范围

- 实现 `/` 公共身份入口。
- 实现 `/hq`、`/partner`、`/teacher`、`/student`、`/parent` 及页面地图中的子路由。
- 建立共用 `RoleShell`、导航、演示数据标识、空状态和基础统计组件。
- 只使用共享 mock repository，不实现真实增删改。

### 完成标准

- 24 个页面路径均可打开，导航和返回入口正确。
- 各端只显示角色范围内的数据。
- 所有页面明确标注演示身份/模拟数据。
- 总部、合作伙伴、教师、家长页面以只读为主。
- 电脑和平板无横向溢出，主要操作可用。

### 测试方式

- 路由 smoke test。
- 五角色页面 E2E：入口 → 端口首页 → 子页 → 返回。
- 角色范围断言：合作伙伴看不到其他校区，教师只看自己班级，家长只看关联孩子。
- 1280×800、1024×768、768×1024 视觉与交互检查。
- lint、类型检查、build。

## 5. 阶段 3：课程学习外壳迁移

### 修改范围

- 将现有课程页迁移到 `/learn/[courseId]/[lessonId]`。
- 保留 `/lessons/[lessonId]` 的兼容跳转，确认稳定后再讨论移除。
- 拆分 `LessonExperience` 的导航、进度、教师预览和渲染职责。
- 统一五个互动组件的输入/输出契约，移除组件内课程特定错误文案。
- 教师预览接入只读 ProgressStore。

### 完成标准

- 同一份课次 JSON 可由学生学习和教师预览使用。
- 学生操作能保存，刷新后恢复到稳定 `stepId`。
- 教师预览不会创建或修改学生进度。
- 现有五类互动原子仍可工作。

### 测试方式

- LessonRenderer 每种原子的组件测试。
- 学生写入与教师只读预览集成测试。
- 旧路由兼容测试。
- 刷新、返回、继续学习 E2E。
- lint、类型检查、build。

## 6. 阶段 4：第 01 课样板

### 修改范围

- 按新大纲制作第 01 课完整 JSON。
- 只复用已确认互动原子；确有新操作模型时，单独评审新增原子。
- 加入教师说明、学生内容和家长摘要。
- 使用预设 AI 演示内容，不调用真实 AI。

### 完成标准

- 完整覆盖“看、讲、想、做、测、说”。
- 学生完成一个可点击欢迎页的演示闭环，并记录至少一处人工修改。
- 课程产出和完成判断与 `docs/03-course-outline.md` 一致。
- 教师端可预览，家长端可读取对应摘要。

### 测试方式

- 课次 JSON Schema 与跨引用测试。
- 六步逐步完成 E2E。
- 错误答案、提示、重新尝试、刷新恢复测试。
- 学生/教师/家长三端内容一致性检查。
- 电脑和平板测试；lint、类型检查、build。

## 7. 阶段 5：第 06 课样板

### 修改范围

- 按新大纲制作第 06 课完整 JSON。
- 使用点击实验、事件表达、代码预览和安全规则检查组合验证组件复用。
- 不实现任意 JavaScript 执行沙箱。

### 完成标准

- 至少一个按钮可以稳定触发预期结果。
- 学生能用“当……时，网页就会……”解释互动。
- “故障按钮”可通过可重复的预设规则检查完成修复。
- 不为第 06 课新增独立页面。

### 测试方式

- 第 06 课 JSON Schema 测试。
- 点击反馈与重新尝试组件测试。
- 故障按钮失败 → 修改 → 通过 E2E。
- 确认第 01/06 课共用同一个 `LessonRenderer`。
- 电脑和平板测试；lint、类型检查、build。

## 8. 阶段 6：样板验收门

### 修改范围

- 不批量写课程。
- 收集第 01/06 课对课程结构、互动原子、AI 模拟、完成规则和教师使用的反馈。
- 只修改样板共同暴露的 Schema/Renderer 问题。

### 完成标准

- 产品方明确确认两节样板可作为其余课次模板。
- 互动原子分为“可复用”“需增强”“待新增”三类。
- Schema 版本可冻结为批量内容接入基线。
- 第 02、07、09、10、11、12、13 课的已知待确认项有处理结论。

### 测试方式

- 产品验收清单逐项签核。
- 两课回归测试全部通过。
- Schema 兼容性测试。

这是批量接入其余课次的强制门槛；未通过时不得开始批量生成。

## 9. 阶段 7：其余 11 课分批接入

### 修改范围

- 仅在样板确认后，按单元分批添加其余 11 课 JSON。
- 先复用现有原子，新增原子必须独立设计、测试并登记关联课次。
- 不复制课次页面，不为单课写专用路由。

### 推荐批次

1. 第 02–05 课：需求、结构、样式、组件。
2. 第 07–09 课：输入输出、条件、状态。
3. 第 10–12 课：应用组合、调试、同伴迭代。
4. 第 13 课：仅在发布方式确认后接入。

### 完成标准

- 5 单元、13 课全部通过 Schema 和引用完整性校验。
- 每课六步完整，目标、产出、完成标准与课程大纲一致。
- 所有课次通过同一 `LessonRenderer` 渲染。
- 教师说明和家长摘要完整。

### 测试方式

- 每批内容校验与抽样完整流程 E2E。
- 所有互动类型组件回归。
- 13 课课程地图、顺序、状态与完成率测试。
- 全量 lint、类型检查、build。

## 10. 阶段 8：整体验收与部署

### 修改范围

- 完成五端与课程系统端到端回归。
- 修复可访问性、电脑/平板布局、演示数据一致性问题。
- 更新 README、页面地图、决策记录和部署说明。

### 完成标准

- `docs/01-product-requirements.md` 第一阶段完成标准全部满足，或明确列出获批例外。
- 五端同源模拟数据一致。
- 学生进度可保存恢复，教师预览只读。
- 网站独立运行与构建成功。

### 测试方式

- 执行 `docs/10-test-plan.md` 全量检查。
- 干净环境安装依赖并构建。
- 生产构建 smoke test。

## 11. 不在本计划中的工作

- 真实账号、密码或第三方登录。
- 正式数据库和多租户权限后台。
- 支付、财务、招生。
- 真实 AI 或语音接口。
- 任意代码执行沙箱。
- 未确认的真实作品发布、公开链接和二维码。
