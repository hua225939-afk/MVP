# Vibe Coding 完整演示版实施计划

## 1. 当前基线

以下工作已完成并作为后续回归基线：

- 五角色演示框架；
- 5 单元、13 课课程清单；
- 第 01 课和第 06 课完整样板 JSON；
- `LessonRenderer` 与 Reveal、Choice、TextInput、CodePreview、RunTest、TaskBuilder 六类互动；
- 学生学习进度的版本化 localStorage 键和教师只读预览。

后续不再经过“一次性 MVP → 推翻重做”的路线。创造台按最终职责边界建设，再逐阶段补齐内容和能力。

## 2. 实施原则

- 课程页与创造台是同一课程系统的两个入口，共用 `ProjectDocument`、工具注册表和 Repository。
- 第 01 课创建主项目，第 02—13 课持续修改同一个 `projectId`。
- 每阶段都能独立演示、测试和验收；未完成的后续工具显示锁定或明确空状态。
- 不删除现有可用功能；样板迁移必须提供进度和产出兼容。
- 不为单课复制页面、组件或项目存储。
- 每阶段运行 lint、类型检查、内容验证、相关测试和 build；页面改动检查电脑与平板。

## 3. 总体顺序

1. 创造台正式底层架构；
2. 第 01—05 课与对应工具；
3. 第 06—09 课与对应工具；
4. 第 10—13 课与对应工具；
5. 五端动态数据联动；
6. 全站测试与部署。

## 4. 阶段 1：创造台正式底层架构

### 4.1 修改范围

- 定义严格 `ProjectDocument`、`ProjectPatch`、版本和角色投影 Zod Schema。
- 实现 `ProjectRepository`/`ProjectStore` 契约及 localStorage 版本。
- 实现项目索引、创建、读取、patch、revision 冲突、迁移和只读适配器。
- 建立 13 个课程工具的注册 Schema、registry、解锁和字段权限。
- 建立 `CourseToolHost`，让课程 JSON 和创造台调用同一工具。
- 实现创造台正式外壳：顶部、左侧插件中心、中间画布、右侧助手、底部抽屉。
- 将课程进度与项目正文分离，但用稳定 ID 关联。
- 为第 01、06 课现有 TaskBuilder 产出设计兼容映射；不在此阶段批量改课。

### 4.2 完成标准

- 能创建一个课程主项目并在刷新后恢复。
- 课程页和创造台对同一项目双向同步。
- 工具不能写入注册表未声明字段；未解锁工具不能提交 patch。
- 同标签页、不同标签页和 revision 冲突行为明确。
- 教师只读适配器的任何写操作都被拒绝。
- 创造台五个页面区域在电脑与平板可用。

### 4.3 测试

- ProjectDocument 合法/非法/迁移 Schema 测试。
- Repository 契约：创建、读取、patch、字段权限、revision 冲突、损坏数据。
- 工具注册完整性：13 工具、课次、组件 key、字段路径和测试规则。
- 课程页 ↔ 创造台同步集成测试。
- 教师只读负向测试。
- 1440×900、1280×800、1024×768、768×1024 布局检查。

## 5. 阶段 2：第 01—05 课与对应工具

### 5.1 工具范围

| 课次 | 工具 | 主要项目字段 |
| --- | --- | --- |
| 01 | 意图画布 | `title/audience/scenario/intent` |
| 02 | 项目边界 | `scope/pages/decisions` |
| 03 | 页面骨架 | `pages/structure` |
| 04 | 外观主题 | `styles/decisions` |
| 05 | 组件中心 | `components/pages/structure` |

### 5.2 修改范围

- 把第 01 课现有样板产出迁入主项目，不丢失学习进度。
- 完成第 02—05 课 JSON、工具基础模式和自由模式。
- 每课加入上一课输入、本课字段权限、测试、造物档案和下一课交接。
- 统一页面/结构/样式/组件的稳定 ID 和引用。

### 5.3 完成标准

- 学生从生活问题连续形成意图、边界、骨架、主题和组件页面。
- 第 05 课结束时仍是第 01 课创建的同一个项目。
- 任何一课上游修改都能在后续工具看到，并使受影响测试待重测。
- 第 01—05 课全部通过课程 Schema、项目绑定和工具引用验证。

### 5.4 测试

- 五课逐课完整六步 E2E。
- 第 01 → 05 跨课字段连续性测试。
- 骨架引用、主题 token、组件位置完整性测试。
- 测试失败 → 返回工具 → 修改 → 重试闭环。
- 教师和家长投影的内容安全测试。

## 6. 阶段 3：第 06—09 课与对应工具

### 6.1 工具范围

| 课次 | 工具 | 主要项目字段 |
| --- | --- | --- |
| 06 | 点击事件 | `interactions/tests` |
| 07 | 输入输出 | `inputs/interactions/tests` |
| 08 | 条件判断 | `conditions/interactions/tests` |
| 09 | 状态记忆 | `state/tests/decisions` |

### 6.2 修改范围

- 把第 06 课现有样板从独立 TaskBuilder 产出迁到第 05 课真实组件。
- 完成第 07—09 课 JSON 和工具。
- 建立交互、输入、条件、状态之间的稳定引用。
- 为测试记录增加被测 revision、失败证据、重试和修复关联。
- 第 09 课运行时刷新策略确认前，以明确 TODO 和可配置测试契约隔离，不静默决定。

### 6.3 完成标准

- 点击、输入、分支和状态都作用于同一 App 的真实页面组件。
- 第 06 课保留连续点击与重置的样板调试闭环。
- 第 08 课所有路径可达；第 09 课增加/减少/重置符合定义。
- 修改事件/输入/条件/状态后相关测试正确失效。

### 6.4 测试

- 事件第一次/连续/重置。
- 正常/空白/过长输入。
- 全分支覆盖与不可达路径。
- 状态连续操作、刷新和重置。
- 第 05 → 09 项目引用完整性和跨课恢复。

## 7. 阶段 4：第 10—13 课与对应工具

### 7.1 工具范围

| 课次 | 工具 | 主要项目字段 |
| --- | --- | --- |
| 10 | 应用合成 | `artifacts/tests/versions` |
| 11 | 故障扫描 | `tests/decisions/versions` |
| 12 | 试玩反馈 | `feedback/decisions/tests/versions` |
| 13 | 作品发布 | `publication/artifacts/versions` |

### 7.2 修改范围

- 第 10 课组合第 01—09 课已有字段生成 1.0，不允许重建空白项目。
- 第 11 课实现复现、单点修改、版本对比和回归，形成 1.1。
- 第 12 课实现试玩任务、原始反馈、排序、采纳理由和二测，形成 2.0。
- 第 13 课实现发布检查、封面、说明、版本选择和发布状态。
- 正式发布方式未确认前，数据和 UI 必须明确区分 `published_demo` 与真实 `published`。

### 7.3 完成标准

- 版本链连续为 1.0 → 1.1 → 2.0 → 发布版。
- 版本对比能定位字段、测试和可见产物变化。
- 同伴反馈保留原始记录和采纳状态。
- 发布只引用通过当前检查的确认版本。
- 观众可按确认的发布方式独立理解并完成核心任务。

### 7.4 测试

- 组合来源完整性和核心流程 E2E。
- 两个可复现 Bug 的修改/回归。
- 试玩前后四项指标、反馈隐私与二测。
- 发布安全、可见范围、电脑/平板、链接/二维码（按确认方式）。
- 全 13 课同一 `projectId` 和版本链断言。

## 8. 阶段 5：五端动态数据联动

### 8.1 修改范围

- 学生端读取完整项目和工具状态。
- 教师端读取班级项目摘要、字段完成度、测试、版本和允许的反馈。
- 家长端读取标题、用途、阶段成果、成长摘要和允许公开的版本。
- 合作伙伴和总部端只读取所属范围的聚合项目/发布数据。
- 统一 mock baseline 与 localStorage project override 的合并逻辑。
- 教师评价使用独立授权记录，不借课程预览修改学生项目。

### 8.2 完成标准

- 五端从同一项目事实生成不同投影，不维护冲突副本。
- 学生修改后，同一浏览器教师/家长投影更新。
- 教师预览、家长查看和运营聚合不改变项目 revision。
- 所有角色范围过滤和隐私字段符合数据模型。

### 8.3 测试

- 五角色 Repository 投影契约。
- 学生保存 → 教师/家长只读更新。
- 教师预览/家长查看零写入。
- 合作伙伴校区范围与总部聚合。
- 项目正文、复杂代码、同伴隐私的负向可见性测试。

## 9. 阶段 6：全站测试与部署

### 9.1 修改范围

- 全 13 课、13 工具、五端、项目迁移和发布回归。
- 可访问性、电脑/平板、性能、localStorage 容量和损坏恢复。
- 更新 README、页面地图、测试计划、决策记录和部署说明。
- 在干净环境执行安装、内容验证、lint、类型检查、测试和生产 build。

### 9.2 完成标准

- 13 课持续项目主线和所有完成判断通过。
- 五端同源数据一致，教师预览只读。
- 页面在电脑和平板无关键阻断。
- 已确认发布方式可完整演示。
- 网站可以独立构建和部署。
- 未确认能力仍明确标注，不以模拟能力冒充真实能力。

## 10. 强制阶段门

- 阶段 1 未通过项目同步、字段权限和迁移测试，不开始批量课程工具开发。
- 每一课程分组未通过跨课连续性测试，不进入下一分组。
- 发布方式未确认，不把 `published_demo` 改为真实 `published`。
- 任一阶段发现需要改变 ProjectDocument 语义时，先提升 `schemaVersion` 并提供迁移。
